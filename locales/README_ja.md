## 意味

- **桜（Sakura）**：幸福、未来への追求、希望への願いを象徴します。
- **签（Sign-In）**：毎日のログイン記録です。
- **樱花签（Sakura SignIn）**：日々の継続と努力を大切にし、ログインするたびに素敵な時間を記録します。

## はじめに

本プロジェクトは Minecraft Forge、Fabric、NeoForge サーバー向けで、毎日のログイン、補填ログイン、設定可能な報酬を提供します。
この MOD はサーバー側に必須で、クライアント側は任意です。クライアント MOD
を導入していないプレイヤーも、コマンドからログイン、報酬受取、抽選、パーソナル日付の設定を利用できます。
クライアント MOD を導入すると、ログインカレンダー、報酬設定エディター、抽選画面、パーソナル日付設定、インベントリのクイック入口を利用できます。

本プロジェクトは [Banira Codex](https://github.com/VanillaXin/BaniraCodex_MC)
に依存し、設定、通知、画面、言語、権限、ローダー間の差異吸収を共通機能として利用します。

## 特徴

- **ログインと補填ログイン**：毎日のログイン、補填カード、一括補填、ログイン後の自動報酬受取、設定可能な補填範囲。
- **多層的な報酬ルール**：基本、連続、周期、年次、月次、週次、日時、累計、ランダムプール、CDK、パーソナル日付、抽選プール。
- **拡張可能な報酬タイプ**：アイテム、エフェクト、経験値、経験レベル、補填カード、進捗、メッセージ、サーバーコマンドを内蔵し、他の
  MOD から新しい報酬タイプを登録可能。
- **視覚的な報酬編集**：ルール別の報酬グループ、多項目選択、ドラッグ、コピーと貼り付け、元に戻すとやり直し、同一報酬の統合、権限制御。
- **パーソナル日付報酬**：サーバーがプリセットを定義し、プレイヤーが暦と日付を選択。年次・月次の繰り返し、ログイン時・オンライン時の配布、有効期限に対応。
- **能動的な抽選**：複数の抽選プール、単発・連続抽選、日次・週次・月次の回数制限、クールダウン、プレビュー権限、複数のクライアント演出。
- **柔軟な一日の境界**：毎日の固定更新時刻、または前回からの時間間隔で次回ログイン可能時刻を計算。
- **オンライン時間制限**：累計オンライン時間と当日のオンライン時間を個別にログイン条件として設定可能。
- **拙い翻訳**: テキストの説明が曖昧だったり、表現が不明瞭だったりする可能性があります <del>（英語に限らず）</del>。
- **拙いコード**: 酷いコード + 杜撰なテスト = 臭いバグの山。

## 設定

樱花签の設定エディター、または以下のファイルを直接編集して設定できます。各項目の意味と有効範囲は、ゲーム内のツールチップおよび生成されたコメントを参照してください。

### 共通ファイル

- 暦ルール [`config/sakura_sign_in/calendar-rules.json`](/config/calendar-rules.json)
- 報酬設定 [`config/sakura_sign_in/reward_option_data.json`](/config/reward_option_data.json)
- 報酬編集履歴 `config/sakura_sign_in/history/`
- 報酬設定バックアップ `config/sakura_sign_in/backups/reward-config/`
- 樱花签のワールドデータ `world/vanilla.xin/sakura_sign_in/`
    - プレイヤーの月別ログイン詳細 `history/<UUID>/<年-月>.nbt`
- 旧プレイヤーデータ移行バックアップ `world/vanilla.xin/backups/sakura_sign_in/`
- Vanilla Xin シリーズ MOD 共通設定 `config/vanilla.xin/common_config.json`（既定言語、ヘルプのページ分割、仮想権限などの共通設定を保存）
- Vanilla Xin シリーズ MOD プレイヤーデータ `world/vanilla.xin/playerdata/*.nbt`（ログイン統計、補填カード、CDK
  記録、個別日付、抽選状態などを保存）

### モジュールファイル

- 共通およびサーバー動作設定 [`config/sakura_sign_in-common.toml`](/config/sakura_sign_in-common.toml)
- クライアント設定 [`config/sakura_sign_in-client.toml`](/config/sakura_sign_in-client.toml)

## コマンド

デフォルトのルートコマンドは `/sakura` です。コマンド名、ルート接頭辞を省略した短縮コマンド、関連権限は設定で変更できます。

- **help**：ページ分けされたコマンドヘルプを表示します。
  **パラメーター**：
    1. `[<ページ>]`
- **sign**：ログインまたは補填ログインを行います。日付を省略すると当日、`all` を指定すると利用可能な補填カードで許可範囲内の未ログイン日を補填します。
  **パラメーター**：
    1. `[<年> <月> <日>]`
    2. `all`
- **reward**：指定したログイン日の報酬を受け取ります。日付を省略すると当日、`all` を指定すると未受取のログイン報酬をすべて受け取ります。
  **パラメーター**：
    1. `[<年> <月> <日>]`
    2. `all`
- **signex**：ログインし、対応する報酬を直ちに受け取ります。
  **パラメーター**：
    1. `[<年> <月> <日>]`
    2. `all`
- **cdk**：引換コードを使用して報酬を受け取ります。
  **パラメーター**：
    1. `<引換コード>`
- **card**：自分の補填カード数を確認するか、管理者がプレイヤーのカードを管理します。
  **パラメーター**：
    1. `give <数量> [<プレイヤー>]`：補填カードを追加
    2. `set <数量> [<プレイヤー>]`：補填カード数を設定
    3. `get <プレイヤー>`：指定プレイヤーの補填カード数を確認
- **lottery**：利用可能な抽選プールを確認するか、抽選を行います。
  **パラメーター**：
    1. `list`
    2. `draw <プール ID> [<回数>|all]`
- **language**：プレイヤーが使用する言語の取得元、または特定の言語を設定します。
  **パラメーター**：
    1. `<client|server|言語コード>`
- **config**：サーバーの共通設定、またはプレイヤー自身のパーソナル日付を変更します。
  **パラメーター**：
    1. `common <設定キー> <設定値>`
    2. `player personalDate [list]`
    3. `player personalDate set <プリセット ID> <スロット> <暦 ID> <日付>`
    4. `player personalDate clear <プリセット ID> <スロット>`

日付引数では、`2026 8 23` のような絶対日付と、`~ ~ ~`、`~ ~ ~-1` のような相対指定を利用できます。デフォルトでは `/sign`、
`/reward`、`/signex`、`/cdk` などの短縮コマンドも登録され、サーバー設定で無効化できます。

## 報酬システム

### 報酬ルール

| ルール       | 説明                                  |
|:----------|:------------------------------------|
| 基本報酬      | ログインするたびに付与                         |
| 連続ログイン報酬  | 指定した連続日数に達した時に付与し、下位段階の再付与も設定可能     |
| 周期ログイン報酬  | 連続ログイン日数に応じて照合し、最大日数を超えた後の再周期化も設定可能 |
| 年次ログイン報酬  | 毎年の指定日にログインすると付与                    |
| 月次ログイン報酬  | 毎月の指定日にログインすると付与                    |
| 週次ログイン報酬  | 毎週の指定曜日にログインすると付与                   |
| 日時報酬      | 指定した日付、時刻、範囲で付与し、年や月など一部要素の無視にも対応   |
| 累計ログイン報酬  | 累計ログイン日数が指定値に達すると付与                 |
| ランダム報酬プール | ログインごとに確率で報酬グループを抽選                 |
| CDK 報酬    | 引換コードで受け取り、使用回数と有効期限を設定可能           |
| パーソナル日付報酬 | サーバーのプリセットとプレイヤーが選択した暦の日付に従って付与     |
| 抽選プール     | プレイヤーが能動的に抽選し、回数、周期、クールダウンで制限       |

### 報酬タイプ

内蔵報酬タイプ：

- アイテムスタック
- エフェクト
- 経験値
- 経験レベル
- 補填カード
- 進捗
- メッセージ
- サーバーコマンド

すべての報酬には個別の確率を設定でき、プレイヤーの幸運値を確率へ反映するかどうかもサーバー側で設定できます。報酬ルールと報酬タイプには、それぞれ権限レベルと
Banira 仮想権限があります。権限のないクライアントには、制限されたルールの詳細設定は送信されません。

他の MOD は `xin.vanilla.sakura.api.reward`
から独自の報酬タイプを登録し、コーデック、検証、付与、説明、統合、任意のクライアント編集・表示機能を提供できます。樱花签の内蔵配布処理を変更する必要はありません。

### 暦とパーソナル日付

樱花签にはグレゴリオ暦と 1900～2100 年の中国農暦ルールが内蔵され、初回起動時に編集可能な `calendar-rules.json`
を生成します。サーバーはこのファイルで暦ルールを補足または置換でき、正常に読み込まれた暦はパーソナル日付設定へ自動的に追加されます。

サーバーが定義するパーソナル日付プリセットでは、設定可能な日付数、利用可能な暦、年次・月次の繰り返し、ログイン時のみ・オンライン時の配布、対象日前後の受取有効期間を制限できます。同じ報酬が正常に付与されるのは一度だけで、期限切れ後は受け取れません。

### 抽選プール

各プールでは、日次、週次、月次の抽選回数、クールダウン、プレビュー範囲を個別に設定できます。クライアント MOD
を導入したプレイヤーは、プールの選択、公開が許可された報酬内容の確認、演出の選択を行えます。抽選結果は常にサーバーが決定し、演出の完了またはスキップ後に報酬が確定して付与されます。

## データと移行

- 累計・連続ログイン日数、補填カード、CDK 記録、パーソナル日付などの概要は Banira プレイヤーデータへ保存
- ログイン詳細はプレイヤーと月ごとに分割し、古い月の詳細を削除しても累計日数、連続日数、以後の報酬計算には影響しない
- `history.retentionMonths` は直近何か月分の詳細を保持するかを設定し、`0` は無期限保持
- `history.retentionPolicy` は期限切れの月ファイル全体を削除するか、容量の大きな報酬スナップショットだけを削除
- 旧プレイヤーデータを検出すると、新形式とバックアップを書き込んで検証してから、旧
  Capability、Attachment、保存ノードを削除。移行に失敗した場合は再試行できるよう旧データを保持
- 旧報酬設定は読み込み時に現在の報酬構造へ変換され、保存後は新形式を使用

セーブデータを移行する前に、ワールドディレクトリ全体をバックアップしてください。サーバーの実行中にプレイヤーデータファイルを手動で削除または移動しないでください。

## ビルド

Minecraft の各バージョンとローダーは、`forge/*`、`fabric/*`、`neoforge/*` ブランチで個別に管理されます。docs
ブランチには、保守対象の全ブランチを構築する共通バッチ入口があります。

```bat
scripts\build-all.bat
```

デフォルトではローカルの全ローダーブランチを構築し、`dev/*`、`maintenance/*` など他の名前空間は含みません。各ブランチは現在の作業ツリーを切り替えず、detached
一時 worktree で構築されます。

ビルドを実行せず、選択されたブランチと JDK 検出だけを確認します。

```bat
scripts\build-all.bat -ListOnly
```

glob 式でブランチを選択できます。

```bat
scripts\build-all.bat -BranchExpression "forge/*"
scripts\build-all.bat -BranchExpression "*/21.1"
scripts\build-all.bat -BranchExpression "forge/*,!forge/16.5"
scripts\build-all.bat -BranchExpression "fabric/18.2"
```

`!` で始まる式は一致するブランチを除外します。以前のパラメーター名 `-Branches` も別名として利用できます。

単一の対象ブランチへ切り替えた後は、直接ビルドすることもできます。

```bat
gradlew.bat clean test assemble
```

成果物は docs 作業ツリーの `builds/<MOD バージョン>/` に集約されます。通常の成果物では Banira Codex を別途導入する必要があり、ファイル名に
`-all` が付く成果物には対応する Banira Codex が含まれます。

現在は Minecraft 1.16.5、1.18.2、1.19.2、1.20.1、1.21.1 を保守しています。NeoForge は 1.21.1 から対応します。`maintenance/*`
以下の旧バージョンブランチは通常の保守対象外です。
