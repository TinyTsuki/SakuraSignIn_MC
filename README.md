## 释义

- **樱花**：象征着幸福、对未来的追求、对希望的期盼。
- **签**：签到。
- **樱花签**：每次签到都是一次美好时光的记录，珍惜每日的坚持和努力。

## 介绍

本项目适用于 Minecraft Forge、Fabric、NeoForge 服务器，为玩家提供每日签到、补签和可配置奖励。
模组需要在服务端安装，客户端可选；未安装客户端的玩家仍可通过指令完成签到、领奖、抽奖和个性化日期配置。
安装客户端后可使用签到日历、奖励配置编辑器、抽奖界面、个性化日期设置和背包快捷入口。

本项目依赖 [Banira Codex](https://github.com/VanillaXin/BaniraCodex_MC)，由其统一提供配置、通知、界面、语言、权限和跨加载器适配能力。

## 特性

- **签到与补签**：支持每日签到、补签卡、批量补签、签到后自动领奖以及可配置的补签范围；
- **多层奖励规则**：支持基础、连续、周期、年度、月度、周度、具体时间、累计、随机池、CDK、个性化日期和抽奖奖池；
- **可扩展奖励类型**：内置物品、药水效果、经验值、经验等级、补签卡、进度、消息和服务端指令，其他模组也可注册新的奖励类型；
- **可视化奖励编辑**：按规则管理奖励组，支持多选、拖动、复制粘贴、撤销重做、合并同类奖励以及权限控制；
- **个性化日期奖励**：服务端定义日期预设，玩家选择历法和日期；支持按年或按月循环、签到发放或在线发放以及领取有效期；
- **主动抽奖**：支持多个奖池、单抽与连抽、每日/每周/每月次数限制、冷却时间、奖池预览权限和多种客户端揭晓动画；
- **灵活的签到日界线**：支持固定时间刷新或按时间间隔计算下一次可签到时间；
- **在线时长限制**：可分别要求玩家达到累计在线时长和当日在线时长后才能签到；
- **很烂的翻译**：文本描述可能存在歧义，或其表达方式不够清晰 <del>（不仅仅是英文）</del>；
- **很烂的代码**：烂代码 + 疏忽的测试 = 一堆难闻的臭虫。

## 配置说明

您可以通过樱花签配置编辑器修改配置，也可以直接编辑下列文件。配置项含义和取值范围以游戏内提示及生成文件中的注释为准。

### 通用部分

- 历法配置 [`config/sakura_sign_in/calendar-rules.json`](/config/calendar-rules.json)
- 奖励配置 [`config/sakura_sign_in/reward_option_data.json`](/config/reward_option_data.json)
- 奖励编辑历史 `config/sakura_sign_in/history/`
- 奖励配置备份 `config/sakura_sign_in/backups/reward-config/`
- 樱花签世界数据 `world/vanilla.xin/sakura_sign_in/`
    - 玩家月度签到详情 `history/<UUID>/<年-月>.nbt`
- 旧版玩家数据迁移备份 `world/vanilla.xin/backups/sakura_sign_in/`
- 香草芯系列模组通用配置 `config/vanilla.xin/common_config.json`（保存默认语言、帮助分页和虚拟权限等共享设置）
- 香草芯系列模组玩家数据 `world/vanilla.xin/playerdata/*.nbt`（保存签到统计、补签卡、CDK、个性化日期和抽奖状态等）

### 模组部分

- 通用及服务器行为配置 [`config/sakura_sign_in-common.toml`](/config/sakura_sign_in-common.toml)
- 客户端相关配置 [`config/sakura_sign_in-client.toml`](/config/sakura_sign_in-client.toml)

## 指令说明

默认根指令为 `/sakura`。指令名称、无根指令前缀的简短指令和相关权限均可在配置中调整。

- **help**：查看分页指令帮助。
  **参数列表**：
    1. `[<页数>]`
- **sign**：签到或补签；不指定日期时签到当前日期，`all` 会使用可用补签卡补齐允许范围内的未签到日期。
  **参数列表**：
    1. `[<年> <月> <日>]`
    2. `all`
- **reward**：领取指定签到日期的奖励；不指定日期时领取当前日期奖励，`all` 会领取全部尚未领取的签到奖励。
  **参数列表**：
    1. `[<年> <月> <日>]`
    2. `all`
- **signex**：签到并立即领取对应奖励。
  **参数列表**：
    1. `[<年> <月> <日>]`
    2. `all`
- **cdk**：使用兑换码领取对应奖励。
  **参数列表**：
    1. `<兑换码>`
- **card**：查询自己的补签卡数量，或由管理员管理玩家补签卡。
  **参数列表**：
    1. `give <数量> [<玩家>]`：增加补签卡
    2. `set <数量> [<玩家>]`：设置补签卡数量
    3. `get <玩家>`：查询指定玩家的补签卡数量
- **lottery**：查看可用奖池或进行抽奖。
  **参数列表**：
    1. `list`
    2. `draw <奖池 ID> [<次数>|all]`
- **language**：设置玩家使用的语言来源或指定语言。
  **参数列表**：
    1. `<client|server|语言代码>`
- **config**：修改服务端通用配置或玩家自己的个性化日期。
  **参数列表**：
    1. `common <配置键> <配置值>`
    2. `player personalDate [list]`
    3. `player personalDate set <预设 ID> <位置> <历法 ID> <日期>`
    4. `player personalDate clear <预设 ID> <位置>`

日期参数支持绝对日期和 `~` 相对写法，例如 `2026 8 23`、`~ ~ ~`、`~ ~ ~-1`。默认还会注册 `/sign`、`/reward`、`/signex` 和
`/cdk` 等简短指令，是否启用以服务端配置为准。

## 奖励系统

### 奖励规则

| 规则      | 说明                             |
|:--------|:-------------------------------|
| 基础奖励    | 每次签到都会获得                       |
| 连续签到奖励  | 连续签到达到指定天数时发放，可配置是否重复获得较低档奖励   |
| 周期签到奖励  | 按连续签到天数匹配，可配置超过最大天数后是否重新循环     |
| 年度签到奖励  | 在每年的指定日期签到时发放                  |
| 月度签到奖励  | 在每月的指定日期签到时发放                  |
| 周度签到奖励  | 在每周的指定星期签到时发放                  |
| 具体时间奖励  | 按指定日期、时间或日期范围发放，支持忽略年份、月份等日期部分 |
| 累计签到奖励  | 累计签到达到指定天数时发放                  |
| 随机奖励池   | 每次签到时按概率从奖励组中抽取                |
| CDK 奖励  | 通过兑换码领取，可限制兑换次数和有效期            |
| 个性化日期奖励 | 按服务端预设与玩家设置的历法日期发放             |
| 抽奖奖池    | 由玩家主动抽取，并受次数、周期和冷却限制           |

### 奖励类型

内置奖励类型包括：

- 物品堆
- 药水效果
- 经验值
- 经验等级
- 补签卡
- 进度
- 消息
- 服务端指令

所有奖励均可单独设置概率，服务端可决定概率是否受玩家幸运值影响。奖励规则和奖励类型分别提供权限等级与 Banira
虚拟权限，未获授权的客户端不会收到对应规则的详细配置。

其他模组可通过 `xin.vanilla.sakura.api.reward` 注册自定义奖励类型，并分别提供编解码、校验、发放、描述、合并和客户端编辑/展示能力，无需修改樱花签内置奖励分发逻辑。

### 历法与个性化日期

樱花签内置公历与 1900～2100 年的农历规则，并在首次运行时生成可编辑的 `calendar-rules.json`
。服务器可在该文件中补充或替换历法规则；加载成功的历法会自动出现在玩家个性化日期设置中。

个性化日期预设由服务端定义，可限制玩家可设置的日期数量、允许使用的历法、按年或按月循环、仅签到时发放或在线即发放，以及日期开始前后可领取的有效天数。同一份奖励只会成功发放一次，过期后不再补发。

### 抽奖奖池

每个奖池可独立配置每日、每周、每月可抽次数、冷却时间和奖池预览范围。安装客户端的玩家可使用抽奖界面选择奖池、查看允许公开的奖励内容，并通过配置选择揭晓动画；抽取结果始终由服务端决定，动画结束或跳过后才会确认并发放奖励。

## 数据与迁移

- 玩家累计签到天数、连续签到天数、补签卡、CDK 记录和个性化日期等摘要由 Banira 玩家数据统一保存
- 签到详情按玩家、月份拆分存储，删除旧月份详情不会影响累计天数、连续天数和后续奖励计算
- `history.retentionMonths` 控制保留最近多少个月的签到详情，`0` 表示永久保留
- `history.retentionPolicy` 可选择删除整个过期月份文件，或仅移除其中体积较大的奖励快照
- 发现旧版玩家数据时，模组会先写入并校验新格式与备份，再清理旧 Capability、Attachment 或旧存储节点；迁移失败时保留旧数据以便下次重试
- 旧版奖励配置会在读取时转换为当前奖励结构，保存后使用新的配置格式

迁移存档前仍建议备份整个世界目录。不要在服务器运行期间手动删除或移动玩家数据文件。

## 构建

各 Minecraft 版本与加载器分别维护在 `forge/*`、`fabric/*`、`neoforge/*` 分支。docs 分支提供统一批量构建脚本：

```bat
scripts\build-all.bat
```

脚本默认构建本地全部加载器分支，不包含 `dev/*`、`maintenance/*` 等其他命名空间。每个分支都在 detached 临时 worktree
中构建，不会切换当前工作树。

仅检查分支与 JDK 配置，不执行构建：

```bat
scripts\build-all.bat -ListOnly
```

通过 glob 表达式选择分支：

```bat
scripts\build-all.bat -BranchExpression "forge/*"
scripts\build-all.bat -BranchExpression "*/21.1"
scripts\build-all.bat -BranchExpression "forge/*,!forge/16.5"
scripts\build-all.bat -BranchExpression "fabric/18.2"
```

`!` 开头的表达式用于排除分支；旧参数名 `-Branches` 仍可作为别名使用。

切换到单个目标分支后也可直接执行：

```bat
gradlew.bat clean test assemble
```

构建产物统一汇总至 docs 工作树的 `builds/<模组版本>/` 目录。普通构建产物依赖独立安装 Banira Codex，文件名带 `-all`
的产物会同时包含对应版本的 Banira Codex。

当前维护 Minecraft 1.16.5、1.18.2、1.19.2、1.20.1 和 1.21.1；NeoForge 从 1.21.1 开始维护。`maintenance/*` 下的旧版本分支不再参与日常维护。
